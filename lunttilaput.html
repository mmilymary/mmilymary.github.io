    Valinta ja toisto

    If päättää, tehdäänkö jotain. While ja for päättää, kuinka monta kertaa.

    Sisennys (neljä välilyöntiä) ei ole koristetta. Pythonissa se on lohkon raja. Ehtoja tarkistetaan ylhäältä alas ja ensimmäinen tosi voittaa.

    pisteet = 72
if pisteet >= 90:
    print("Kiitettävä")
elif pisteet >= 50:
    print("Hyväksytty")    # ← tämä tulostuu
else:
    print("Hylätty")

    range

    Muoto on range(alku, loppu, askel). Loppu ei tule mukaan. Koskaan.

    list(range(5))          # [0, 1, 2, 3, 4]
list(range(2, 6))       # [2, 3, 4, 5]
list(range(10, 0, -3))  # [10, 7, 4, 1]

    for vs. while

    For, kun tiedät mitä käydään läpi. While, kun toistetaan niin kauan kuin joku ehto on voimassa.

    for i in range(3):
    print(i)        # 0, 1, 2

n = 3
while n > 0:
    print(n)        # 3, 2, 1
    n -= 1          # unohda tämä, niin silmukka ei lopu ikinä

for i in range(10):
    if i == 2:
        continue    # hyppää tämän kierroksen yli
    if i == 5:
        break       # lopettaa koko silmukan
    print(i)        # 0, 1, 3, 4

    Olio-ohjelmointi

    Luokka on muotti, olio on siitä valettu kappale. self tarkoittaa "tämä nimenomainen kappale".

    class Kurssi:
    def __init__(self, nimi: str, op: int):   # ajetaan kun olio luodaan
        self.nimi = nimi                      # tietojäsenet
        self.op = op
        self.valmis = False

    def suorita(self):                        # metodi
        self.valmis = True

    def __str__(self):                        # mitä print näyttää
        tila = "valmis" if self.valmis else "kesken"
        return f"{self.nimi} ({self.op} op, {tila})"

    @classmethod
    def tekstista(cls, rivi: str):            # luokkametodi: saa luokan, ei oliota
        nimi, op = rivi.split(";")
        return cls(nimi, int(op))

python = Kurssi("Python", 5)
python.suorita()
print(python)                          # Python (5 op, valmis)
print(Kurssi.tekstista("Tietoverkot;5"))  # Tietoverkot (5 op, kesken)
    Sudenkuoppa

    Jokainen metodi tarvitsee self-parametrin ensimmäiseksi. Ja self.nimi on olion tieto, pelkkä nimi on vain paikallinen muuttuja, joka katoaa funktion lopussa.

    Harjoitus 8

    Tee luokka Tili, jolla on talleta(summa), nosta(summa) ja saldo. Nosto ei saa viedä saldoa miinukselle, vaan palauttaa silloin False.

    Näytä vihje

    Tarkista ensin, riittääkö saldo. Vähennä vasta sen jälkeen.

    Näytä ratkaisu
    class Tili:
    def __init__(self, omistaja: str):
        self.omistaja = omistaja
        self.saldo = 0

    def talleta(self, summa: float):
        self.saldo += summa

    def nosta(self, summa: float) -> bool:
        if summa > self.saldo:
            return False
        self.saldo -= summa
        return True

tili = Tili("Ada")
tili.talleta(50)
print(tili.nosta(80))   # False
print(tili.nosta(20))   # True
print(tili.saldo)       # 30

      SELECT

      Jokainen kysely alkaa kahdella asialla: mitkä sarakkeet (SELECT) ja mistä taulusta (FROM). Tähti tarkoittaa kaikkia sarakkeita. Kysely päättyy puolipisteeseen.

      Hyvä tietää

      • SQL jaetaan usein kolmeen osaan. DDL määrittää rakenteen (CREATE, ALTER, DROP), DML käsittelee tietoja (SELECT, INSERT, UPDATE, DELETE) ja DCL hallitsee käyttöoikeuksia (GRANT). SQLitessa ei ole käyttäjiä, joten DCL-käskyjä siinä ei ole.
      • SQL-käskyissä isoilla ja pienillä kirjaimilla ei ole väliä, merkkijonoissa on.
      • Jos painat Enteriä ennen puolipistettä, SQLite näyttää jatkokehotteen ...> ja odottaa loppua. Jos kaikki menee sekaisin, Ctrl+C keskeyttää.

      Osa 3 · to 22.10.WHERE · AND/OR · IN · BETWEEN · LIKE · NULL

      Ehdot ja tyhjät arvot

      WHERE päättää, mitkä rivit pääsevät tulokseen. NULL tarkoittaa, ettei arvoa tiedetä, eikä sitä voi verrata yhtäsuuruusmerkillä.

      SELECT nimi FROM kirja WHERE vuosi < 1840;
-- Frankenstein, Usherin talon häviö, Arthur Gordon Pymin seikkailut

SELECT nimi, vuosi FROM kirja
WHERE vuosi BETWEEN 1840 AND 1850       -- molemmat päät mukana
ORDER BY vuosi;
-- Korppi 1845, Humiseva harju 1847, Kalevala 1849

SELECT nimi FROM kirja WHERE kirjailija_id IN (2, 3);   -- Poe ja Lovecraft
-- Usherin talon häviö, Cthulhun kutsu, Korppi, Hulluuden vuorilla,
-- Arthur Gordon Pymin seikkailut

      AND ja OR

      SELECT nimi FROM kirja WHERE sivut > 200 AND hinta < 20;
-- Humiseva harju, Frankenstein

SELECT nimi FROM kirja WHERE vuosi < 1840 OR sivut > 400;
-- Humiseva harju, Frankenstein, Dracula, Usherin talon häviö,
-- Arthur Gordon Pymin seikkailut

      Arthur Gordon Pymin seikkailut (256 sivua) puuttuu ensimmäisestä tuloksesta, koska sen hinta on NULL. NULL ei ole pienempi eikä suurempi kuin 20, joten ehto ei ole tosi.

      LIKE

      % tarkoittaa mitä tahansa määrää merkkejä ja _ tasan yhtä merkkiä.

      SELECT nimi FROM kirja WHERE nimi LIKE 'H%';
-- Humiseva harju, Hulluuden vuorilla

SELECT nimi FROM kirja WHERE nimi LIKE '%talo%';
-- Usherin talon häviö

      NULL

      SELECT nimi FROM kirja WHERE hinta IS NULL;
-- Korppi, Arthur Gordon Pymin seikkailut

SELECT nimi, IFNULL(hinta, 'ei tiedossa') FROM kirja WHERE id IN (5, 6);
-- Cthulhun kutsu  11.9
-- Korppi          ei tiedossa

      WHERE hinta = NULL ei anna virhettä, mutta ei myöskään yhtään riviä. Käytä aina IS NULL tai IS NOT NULL.

      Osa 5 · to 5.11.JOIN · LEFT JOIN · aliakset

      Taulujen liitokset

      JOIN yhdistää kaksi taulua sarakkeen kautta, joka on molemmissa. Kirjassa on kirjailija_id, ja se vastaa kirjailijataulun id:tä.

      SELECT kirja.nimi, kirjailija.nimi
FROM kirja
JOIN kirjailija ON kirja.kirjailija_id = kirjailija.id
ORDER BY kirja.vuosi
LIMIT 3;
-- Frankenstein                    Mary Shelley
-- Arthur Gordon Pymin seikkailut  Edgar Allan Poe
-- Usherin talon häviö             Edgar Allan Poe

      Lyhyet aliakset (k, a, l) säästävät kirjoittamista, kun tauluja on monta.

      SELECT l.lainaaja, k.nimi
FROM lainaus l
JOIN kirja k ON l.kirja_id = k.id
WHERE l.palautettu IS NULL
ORDER BY l.lainaaja;
-- Ada    Frankenstein
-- Grace  Cthulhun kutsu
-- Grace  Dracula

      LEFT JOIN

      Tavallinen JOIN pudottaa rivit, joille ei löydy paria. Kalevalalla ei ole kirjailijaa, joten liitoksessa on 8 kirjaa eikä 9. LEFT JOIN pitää kaikki vasemman taulun rivit ja täyttää puuttuvat kohdat NULLilla.

      SELECT k.nimi
FROM kirja k
LEFT JOIN lainaus l ON l.kirja_id = k.id
WHERE l.id IS NULL
ORDER BY k.nimi;
-- kirjat, joita ei ole lainattu kertaakaan:
-- Arthur Gordon Pymin seikkailut, Hulluuden vuorilla, Kalevala, Korppi,
-- Usherin talon häviö
      Sudenkuoppa

      Jos LEFT JOINin oikean taulun ehto kirjoitetaan WHERE-osaan, NULL-rivit putoavat pois ja liitos toimii kuin tavallinen JOIN. Ehto kuuluu silloin ON-osaan.

      -- kaikki kirjailijat, ja vuoden 1840 jälkeiset kirjat jos niitä on
SELECT a.nimi, k.nimi
FROM kirjailija a
LEFT JOIN kirja k ON k.kirjailija_id = a.id AND k.vuosi > 1840
ORDER BY a.nimi, k.nimi;
-- Mary Shelley näkyy NULLin kanssa, koska Frankenstein on vuodelta 1818.
-- Siirrä ehto WHEREen, niin hän katoaa kokonaan.

      Näkymät ja indeksit

      Näkymä on tallennettu kysely, jota käytetään kuin taulua. Indeksi on hakemisto, joka nopeuttaa hakuja isoissa tauluissa.

      Näkymä

      CREATE VIEW lainassa AS
SELECT l.lainaaja, k.nimi, l.lainattu
FROM lainaus l
JOIN kirja k ON k.id = l.kirja_id
WHERE l.palautettu IS NULL;

SELECT * FROM lainassa ORDER BY lainattu;

-- Grace  Cthulhun kutsu  2026-09-18

      EXPLAIN QUERY PLAN kertoo, miten SQLite aikoo hakea rivit. SCAN tarkoittaa, että se käy koko taulun läpi. SEARCH ... USING INDEX tarkoittaa, että se hyppää suoraan oikeisiin riveihin.

      EXPLAIN QUERY PLAN SELECT * FROM kirja WHERE vuosi = 1897;
-- SCAN kirja

CREATE INDEX idx_kirja_vuosi ON kirja(vuosi);

EXPLAIN QUERY PLAN SELECT * FROM kirja WHERE vuosi = 1897;
-- SEARCH kirja USING INDEX idx_kirja_vuosi (vuosi=?)
      Sudenkuoppa

      Indeksi ei ole ilmainen. Se vie tilaa, ja jokainen INSERT ja UPDATE joutuu päivittämään myös indeksin. Indeksoi sarakkeet, joilla oikeasti haetaan tai liitetään.

      SQLiten valmiit funktiot

      Osa funktioista käsittelee yhtä arvoa kerrallaan, kuten upper. Koostefunktiot, kuten COUNT ja AVG, tiivistävät monta riviä yhdeksi luvuksi.

      Teksti ja päivämäärät

SELECT substr(nimi, 1, 5) FROM kirja WHERE id = 1;          -- Humis
SELECT nimi || ' (' || vuosi || ')' FROM kirja WHERE id = 3; -- Dracula (1897)

SELECT julianday('2026-10-01') - julianday('2026-09-15');     -- 16.0

      Koostefunktiot

      SELECT COUNT(*), COUNT(hinta) FROM kirja;   -- 9  7   (COUNT(sarake) ohittaa NULLit)

SELECT round(AVG(hinta), 2), MIN(hinta), MAX(hinta), SUM(sivut) FROM kirja;
-- 16.47  8.5  24.0  2208

      GROUP BY ja HAVING

      GROUP BY laskee koosteen erikseen jokaiselle ryhmälle. WHERE rajaa rivejä ennen ryhmittelyä, HAVING ryhmiä sen jälkeen.

      SELECT a.nimi, COUNT(k.id) AS kirjoja, round(AVG(k.sivut)) AS sivuja_keskim
FROM kirjailija a
JOIN kirja k ON k.kirjailija_id = a.id
GROUP BY a.id, a.nimi
HAVING COUNT(k.id) >= 2
ORDER BY a.nimi;
-- Edgar Allan Poe  3  123.0
-- H. P. Lovecraft  2  128.0

      CASE

      SELECT nimi,
  CASE WHEN sivut > 400 THEN 'tiiliskivi'
       WHEN sivut > 150 THEN 'keskikokoinen'
       ELSE 'ohut' END AS koko

      Osa 9 · to 3.12.BEGIN · COMMIT · ROLLBACK

      Transaktiot

      Transaktio niputtaa monta muutosta yhdeksi. Joko kaikki onnistuvat, tai mikään ei jää voimaan.

      Tavallinen esimerkki on tilisiirto: rahan pitää lähteä yhdeltä tililtä ja tulla toiselle. Jos jälkimmäinen epäonnistuu, myös ensimmäinen perutaan.

      CREATE TABLE tili (nimi TEXT PRIMARY KEY, saldo INTEGER CHECK (saldo >= 0));
INSERT INTO tili VALUES ('Ada', 100), ('Linus', 20);

BEGIN;
UPDATE tili SET saldo = saldo + 50 WHERE nimi = 'Ada';
UPDATE tili SET saldo = saldo - 50 WHERE nimi = 'Linus';
-- CHECK constraint failed: saldo >= 0
ROLLBACK;

SELECT * FROM tili;
-- Ada    100
-- Linus  20     ← Adankaan saldo ei muuttunut

      Hätäjarru

      ROLLBACK peruu kaikki muutokset takaisin transaktion alkuun, myös vahingossa tehdyt.

      BEGIN;
DELETE FROM lainaus;               -- oho, kaikki lainat lähti
SELECT COUNT(*) FROM lainaus;      -- 0
ROLLBACK;
SELECT COUNT(*) FROM lainaus;      -- 5

      AtomicityKaikki tai ei mitään.
      ConsistencySäännöt pitävät transaktion jälkeenkin.
      IsolationKeskeneräiset muutokset eivät näy muille.
      DurabilityHyväksytty muutos säilyy, vaikka virta katkeaisi.
      Sudenkuoppa

      Virhe transaktion keskellä ei peru aiempia muutoksia itsestään. Ne jäävät odottamaan, ja jos seuraavaksi annetaan COMMIT, puolikas muutos tallentuu. Virheen jälkeen tulee ROLLBACK.

        Osa 6Aliverkon peite · CIDR · AND

        Mikä osa osoitteesta on verkkoa

        Aliverkon peite on jono ykkösiä ja sen perässä nollia. Ykköset merkitsevät verkko-osaa, nollat laiteosaa. CIDR-merkintä /24 kertoo ykkösten määrän.

        CIDRPeiteLaitebittejäLaitteita
        /24255.255.255.082⁸ − 2 = 254
        /21255.255.248.0112¹¹ − 2 = 2046
        /26255.255.255.19262⁶ − 2 = 62

        Laitteiden määrästä vähennetään kaksi, koska verkossa on kaksi varattua osoitetta. Ensimmäinen, jossa kaikki laitebitit ovat nollia, on verkko-osoite. Viimeinen, jossa kaikki laitebitit ovat ykkösiä, on yleislähetysosoite (broadcast).

        Verkko-osoite AND-operaatiolla

        AND antaa ykkösen vain, jos molemmat bitit ovat ykkösiä. Kun osoite ja peite AND-ataan bitti kerrallaan, laiteosa nollautuu ja jäljelle jää verkko-osoite.

        172.16.13.200/21

Osoite    10101100.00010000.00001101.11001000   172.16.13.200
Peite     11111111.11111111.11111000.00000000   255.255.248.0
AND       10101100.00010000.00001000.00000000   172.16.8.0      ← verkko-osoite

Yleislähetys: laitebitit ykkösiksi          →   172.16.15.255
Laitteille:   172.16.8.1 – 172.16.15.254   (2046 osoitetta)

        Oktetit, joissa peite on 255, pysyvät sellaisenaan, ja oktetit, joissa peite on 0, muuttuvat nolliksi. Bitteinä tarvitsee laskea vain se oktetti, jossa peite vaihtuu kesken.

        Tarkista Pythonilla

        import ipaddress
verkko = ipaddress.ip_network("172.16.13.200/21", strict=False)
verkko.network_address     # 172.16.8.0
verkko.broadcast_address   # 172.16.15.255
verkko.netmask             # 255.255.248.0
        Sudenkuoppa

        /21-verkon verkko-osoite ei ole 172.16.13.0, vaikka se näyttäisi luontevalta. Peite leikkaa kolmannen oktetin keskeltä, joten 13 täytyy laskea bitteinä: 00001101 AND 11111000 = 00001000 eli 8.

        IPv6 ja sen lyhentäminen

        IPv6-osoite on 128 bittiä: kahdeksan 16 bitin ryhmää eli hekstettiä. Jokainen hekstetti kirjoitetaan neljällä heksamerkillä, ja ryhmät erotetaan kaksoispisteillä.

        2001:0db8:0000:0000:0000:ff00:0042:8329

Yksi hekstetti bitteinä nippusäännöllä:
0db8  →  0000 1101 1011 1000

        Kirjaimet voi kirjoittaa isoina tai pieninä, mutta suositus on pienet kirjaimet.

        Tiivistyksen kaksi sääntöä

        1. Jokaisesta hekstetistä saa jättää etunollat pois: 0db8 → db8, 0042 → 42, 0000 → 0.
        2. Yhden peräkkäisten nollahekstettien jonon saa korvata merkillä ::, mutta vain kerran osoitteessa.
        2001:0db8:0000:0000:0000:ff00:0042:8329
2001:db8:0:0:0:ff00:42:8329          ← etunollat pois
2001:db8::ff00:42:8329               ← nollajono ::-merkiksi

        Tarkista Pythonilla

        import ipaddress
ipaddress.ip_address("2001:0db8:0000:0000:0000:ff00:0042:8329").compressed
# '2001:db8::ff00:42:8329'
ipaddress.ip_address("2001:db8:a::1").exploded
# '2001:0db8:000a:0000:0000:0000:0000:0001'
        Sudenkuoppa

        :: saa esiintyä vain kerran. Jos niitä olisi kaksi, ei voisi tietää, montako nollaryhmää kumpikin tarkoittaa. Kun nollajonoja on kaksi yhtä pitkää, tiivistetään ensimmäinen: 2001:db8:0:0:1:0:0:1 → 2001:db8::1:0:0:1.

        Hekstetin lopussa olevia nollia ei saa poistaa. ff00 pysyy ff00:na, koska ff tarkoittaisi 00ff:ää.

        Harjoitus 7

            Lähettäessä jokainen kerros lisää datan ympärille oman otsikkonsa: kuljetuskerros porttinumerot, verkkokerros IP-osoitteet eli loogiset osoitteet ja siirtoyhteyskerros MAC-osoitteet eli fyysiset osoitteet.             DHCP säästää ylläpidon työtä ja poistaa käsin tehdyt asetusvirheet. Osoite on laina (lease): kun sitä ei enää käytetä, se palaa vapaiden osoitteiden joukkoon.

            #ViestiKuka lähettääMitä tapahtuu
            1DHCPDISCOVERasiakas, broadcastKysyy, onko verkossa DHCP-palvelinta. Kohdeosoite 255.255.255.255.
            2DHCPOFFERpalvelinTarjoaa osoitetta
            3DHCPREQUESTasiakas, broadcastHyväksyy tarjouksen
            4DHCPACKpalvelinVahvistaa lainan

            Kaikki lähiverkon laitteet vastaanottavat asiakkaan broadcastit, mutta vain DHCP-palvelin vastaa. Kotireititin on itsekin DHCP-asiakas: se saa julkisen osoitteensa operaattorin DHCP-palvelimelta.

            Suoraan vai reitittimelle

            Ennen lähettämistä laite tekee oman peitteensä ja kohteen IP-osoitteen välillä AND-laskun. Jos tulos on sama kuin oma verkko-osoite, kohde on samassa verkossa.

            KohdeKehyksen kohde-MACPaketin kohde-IP
            Samassa verkossakohdelaitteen MACkohdelaitteen IP
            Toisessa verkossaoman oletusyhdyskäytävän MACedelleen lopullisen kohteen IP

            MAC-osoitteen laite selvittää ARPilla:

            1. Laite lähettää ARP-pyynnön broadcastina MAC-osoitteeseen FFFF.FFFF.FFFF: kenellä on tämä IP-osoite?
            2. Kaikki lähiverkon laitteet vastaanottavat pyynnön.
            3. Vain se, jonka IP-osoite täsmää, vastaa ja kertoo oman MAC-osoitteensa.

            IPv6:ssa saman tehtävän hoitaa ND (Neighbor Discovery). MAC-osoitteet ja IPv6-osoitteet kirjoitetaan heksadesimaaleina.

            Reititin

            • Reitittimen kaksi tehtävää ovat polun valinta ja pakettien välitys. Se katsoo paketin kohde-IP-osoitetta ja vertaa sitä reititystauluunsa.
            • Reititystaulussa kirjain C tarkoittaa suoraan kytkettyä verkkoa (directly connected).
            • Oletusreitti on reitti, jota käytetään, kun kohdeverkkoa ei löydy taulusta. Jos sitäkään ei ole, reititin pudottaa paketin.
            • Reititin purkaa jokaisen kehyksen ja rakentaa sen uudelleen uusilla MAC-osoitteilla. IP-osoitteet pysyvät samoina.
            • Reititin ei välitä broadcasteja toiseen verkkoon. Siksi verkon jakaminen reitittimillä pienentää broadcast-alueita, parantaa suorituskykyä ja tietoturvaa ja antaa laajentaa verkon toiseen paikkaan.

            NAT muuntaa sisäverkon yksityiset osoitteet reitittimen ulkoliitännän julkiseksi osoitteeksi. Näin kaikki kodin laitteet voivat jakaa yhden julkisen IPv4-osoitteen.

            Siirtyminen IPv6:een

            IPv6 tarvitaan, koska IPv4-osoitteet loppuvat. Pelkästään esineiden internet tuo verkkoon miljoonia sensoreita, joista jokainen tarvitsee osoitteen.

            TunnelointiIPv6-paketti kulkee IPv4-paketin sisällä
            Muunnos (NAT64)IPv6-laite ja IPv4-laite keskustelevat muunnoksen kautta

            Osa 6CIA · riski · liiketoiminta

            Miksi kyberturva kuuluu liiketoimintaan

            Kyberturvassa suojataan tietoa ja palveluita, joiden varassa yritys toimii. Kun järjestelmät pysähtyvät, myös myynti, tuotanto ja asiakaspalvelu pysähtyvät.

            CIA-kolmio

            TavoiteTarkoittaaEsimerkki
            Luottamuksellisuus (Confidentiality)Tieto on vain niiden käytössä, joilla on siihen oikeus.salaus, käyttöoikeudet
            Eheys (Integrity)Tieto on oikeaa, eikä sitä ole muutettu luvatta.tiivisteet, digitaaliset allekirjoitukset
            Saatavuus (Availability)Tieto ja palvelut ovat käytettävissä silloin, kun niitä tarvitaan.varmuuskopiot, varajärjestelmät

            Riski

            Riskiä arvioidaan kahdella kysymyksellä: kuinka todennäköisesti jokin tapahtuu ja kuinka pahat seuraukset sillä on. Kaikkea ei voi suojata yhtä paljon, joten suojaukset kohdistetaan suurimpiin riskeihin.

            Mitä huono kyberturva maksaa

            • Käyttökatko: myynti ja tuotanto pysähtyvät.
            • Maine: asiakkaat ja kumppanit menettävät luottamuksensa.
            • Sakot: EU:n tietosuoja-asetuksen (GDPR) rikkomisesta voi seurata enintään 20 miljoonan euron tai 4 prosentin maailmanlaajuisen vuosiliikevaihdon sakko, sen mukaan kumpi on suurempi.
            • Johdon vastuu: NIS2-direktiivin mukaan organisaation johto hyväksyy kyberturvatoimet ja vastaa niistä.
            Sudenkuoppa

            Tietoturva ei ole pelkästään IT-osaston asia. Suuri osa onnistuneista hyökkäyksistä hyödyntää ihmistä, esimerkiksi huijausviestillä, joten koulutus kuuluu jokaiselle.

            Näytä vihje

            Kysy jokaisesta: katosiko pääsy, näkikö väärä ihminen, vai muuttuiko tieto?

            Näytä ratkaisu
            a) saatavuus

            Osa 7Uhat · varautuminen

            Kyberuhat ja niihin varautuminen

            Useimmat hyökkäykset eivät ole teknisesti nokkelia. Ne hyödyntävät kiirettä, heikkoja salasanoja ja päivittämättömiä järjestelmiä.

            UhkaMitä tapahtuu
            TietojenkalasteluHuijausviesti houkuttelee klikkaamaan linkkiä tai antamaan tunnukset.
            KiristyshaittaohjelmaSalaa tiedostot ja vaatii lunnaita. Usein tietoja myös varastetaan ja uhataan julkaista.
            VirusKiinnittyy toiseen tiedostoon ja leviää, kun tiedosto avataan.
            MatoLeviää itsestään verkon yli ilman käyttäjän toimia.
            TroijalainenNäyttää hyödylliseltä ohjelmalta, mutta sisältää haitallisen osan.
            DoS / DDoSPalvelu kaadetaan liialla liikenteellä. DDoS-hyökkäyksessä liikenne tulee monesta lähteestä yhtä aikaa.
            Väliintulohyökkäys (MitM)Hyökkääjä asettuu kahden osapuolen väliin ja kuuntelee tai muuttaa liikennettä.
            Sosiaalinen manipulointiIhminen huijataan antamaan tietoja tai pääsy, esimerkiksi esiintymällä toimitusjohtajana.

            Varautuminen

            • Monivaiheinen tunnistautuminen (MFA): pelkkä varastettu salasana ei riitä.
            • Päivitykset: tunnetut haavoittuvuudet paikataan ennen kuin niitä käytetään hyväksi.
            • Varmuuskopiot 3-2-1-säännöllä: kolme kopiota, kahdella eri tallennusmedialla, joista yksi eri paikassa. Palautusta pitää myös testata.
            • Vähimmät oikeudet: jokaisella on vain ne oikeudet, joita työ vaatii.
            • Verkon segmentointi: verkko jaetaan osiin, ettei yksi murto avaa koko verkkoa.
            • Koulutus ja ilmoituskanava: epäilyttävästä viestistä on helppo ilmoittaa, eikä ketään syyllistetä.

            Suomessa tietoturvaloukkauksista voi ilmoittaa Traficomin Kyberturvallisuuskeskukselle.

            Sudenkuoppa

            Varmuuskopio, joka on koko ajan kiinni samassa verkossa, voi salautua kiristyshaittaohjelman mukana. Ainakin yhden kopion pitää olla erillään verkosta tai muuttumattomana tallennettuna.

            Osa 8ISO/IEC 27001 · NIS2 · Kybermittari · NIST CSF

            Kyberturvan keskeiset standardit

            Standardit ja säädökset kertovat, mitä kyberturvassa pitää vähintään hoitaa ja miten sen voi osoittaa muille.

            NimiMikä se on
            ISO/IEC 27001Kansainvälinen standardi tietoturvan hallintajärjestelmälle (ISMS). Organisaatio voi hakea sille sertifikaatin. Uusin versio on vuodelta 2022.
            ISO/IEC 27002Ohjeet 27001:n hallintakeinojen toteuttamiseen.
            NIS2EU:n kyberturvallisuusdirektiivi (EU) 2022/2555. Suomessa se pannaan täytäntöön kyberturvallisuuslailla (124/2025), joka tuli voimaan 8.4.2025.
            GDPREU:n tietosuoja-asetus (EU) 2016/679, jota on sovellettu 25.5.2018 alkaen. Koskee henkilötietoja.
            KybermittariKyberturvallisuuskeskuksen maksuton työkalu, jolla organisaatio arvioi oman kyberturvansa tasoa.
            NIST CSF 2.0Yhdysvaltalainen, laajasti käytetty kehys. Kuusi toimintoa: Govern, Identify, Protect, Detect, Respond ja Recover.

            NIS2 lyhyesti

            • Koskee keskisuuria ja suuria organisaatioita, jotka toimivat direktiivissä luetelluilla aloilla, kuten energia, liikenne, terveydenhuolto ja digitaalinen infrastruktuuri. Osa toimijoista, esimerkiksi DNS-palveluiden tarjoajat, kuuluu piiriin koosta riippumatta.
            • Johdon on hyväksyttävä riskienhallintatoimet ja osallistuttava koulutukseen.
            • Merkittävästä poikkeamasta annetaan varhainen varoitus 24 tunnin kuluessa, ilmoitus 72 tunnin kuluessa ja loppuraportti kuukauden kuluessa.
            Sudenkuoppa

            ISO/IEC 27001 on vapaaehtoinen standardi. GDPR on suoraan sovellettava EU-asetus, ja NIS2 velvoittaa Suomessa kyberturvallisuuslain kautta. Sertifikaatti ei yksinään tarkoita, että lakisääteiset velvoitteet on täytetty, vaikka se auttaa niissä paljon.
